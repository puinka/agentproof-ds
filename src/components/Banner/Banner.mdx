# Banner

A status message inside the page, placed above the content it is about. It informs; it does not promote. The lime "Highlight banner" on marketing pages is a different thing.

## Anatomy

| Element | Description |
|---|---|
| **Icon** | Set by `status`. Decorative: the title says the status in words. |
| **Title** | Required. Starts with the point: "Payment sent". |
| **Body** | One or two sentences: what it means and what to do. |
| **Action** | Optional, one. A link-style Button or a link. |
| **Dismiss** | Optional. Only when the message isn't needed again. |

## Best practices

| | Guidance |
|---|---|
| ✅ Do | Pick the status by consequence: `error` blocks the task, `warning` will block it later, `success` confirms, `info` explains. |
| ✅ Do | Leave `live` off for banners that are on the page when it loads. They are read in order. |
| ✅ Do | Use `live="polite"` for a result that appears after an action, `live="assertive"` only for an error that stops the current task. |
| ❌ Don't | Stack several banners. Merge them, or keep the most severe. |
| ❌ Don't | Use a banner for form field errors. Put those on the field. |

- The status is in the title text and the icon shape, never in the colour alone (1.4.1).
- `live="assertive"` renders `role="alert"`, `live="polite"` renders `role="status"`. A polite banner is announced most reliably when it appears inside an area that was already on the page.
- The dismiss button needs a specific name when there are several banners: `dismissLabel="Dismiss: New pay-out option"`.
